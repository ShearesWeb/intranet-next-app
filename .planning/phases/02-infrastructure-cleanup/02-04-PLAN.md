Per D-12 (standalone Prettier, not ESLint plugin) and D-13 (tabs, double quotes, semicolons):

**Step 1: Install Prettier**
```bash
npm install --save-dev prettier
```

**Step 2: Create `.prettierrc`** with the following exact content:
```json
{
    "useTabs": true,
    "tabWidth": 2,
    "semi": true,
    "singleQuote": false,
    "trailingComma": "all",
    "printWidth": 100
}
```

Rationale for each setting:
- `useTabs: true` -- per D-13, tabs for indentation
- `tabWidth: 2` -- visual width of tabs
- `semi: true` -- per D-13, semicolons
- `singleQuote: false` -- per D-13, double quotes (matches JSX convention)
- `trailingComma: "all"` -- matches existing codebase pattern
- `printWidth: 100` -- Claude's discretion. 80 causes excessive wrapping in JSX files, 120 is too wide for review. 100 is the standard middle ground.

**Step 3: Create `.prettierignore`** with the following exact content:
```
node_modules/
.next/
.sst/
dist/
coverage/
package-lock.json
```

**Step 4: Add a format script to package.json**

Add to the "scripts" section:
```json
"format": "prettier --write \"src/**/*.{ts,tsx,js,jsx,json,css,md}\"",
"format:check": "prettier --check \"src/**/*.{ts,tsx,js,jsx,json,css,md}\""
```

Verify Prettier is installed:
```bash
npx prettier --version
```

Run the one-time format pass across all source files:

```bash
npx prettier --write "src/**/*.{ts,tsx}"
npx prettier --write "*.{mjs,json}" --ignore-path .prettierignore
```

This will reformat all TypeScript/TSX files in src/ plus root config files (next.config.mjs, etc.) according to the .prettierrc settings.

After formatting, verify:
1. The format check passes (no unformatted files):
```bash
npx prettier --check "src/**/*.{ts,tsx}"
```

2. The build still passes (formatting changes should not break functionality):
```bash
npm run build
```

3. Tests still pass:
```bash
npm test
```

If the build fails after formatting, the issue is likely Prettier conflicting with ESLint. Per RESEARCH.md pitfall 5, the current ESLint config has no formatting rules that conflict with Prettier. If any issue arises, check for ESLint rules that enforce specific formatting (unlikely with next/core-web-vitals + next/typescript).

IMPORTANT: Do NOT run `prettier --write` on `package-lock.json` (it's in .prettierignore). Do NOT format files in `node_modules/`, `.next/`, or `.sst/`.
  </action>
