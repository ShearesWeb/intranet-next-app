Purpose: this is the phase's tracer slice plus the two expansion steps that finish the boundary. Once it lands, no API response can carry the excluded venue type and no client can create a claim on one — which is what makes every later cleanup task a deletion rather than a behaviour change.

Output: a shared predicate in `src/types/facilities.ts`, three excluding reads in `src/lib/facilities/`, a bookable-type gate on the claims POST, the role-conditional slots branch and the four horizon helpers deleted, and unit coverage for each of the three reads.
</objective>

## Planner decisions recorded for this phase

CONTEXT.md left four items to the planner. They are resolved here and are binding on every plan in this phase:

- **D-10 status code: `400`.** The request asks to book a venue class the intranet does not serve, which is a malformed request in intent rather than a permission failure. `403` was correct for the old time-window rule; it is not correct for a class of venue that is never bookable. Error text: `This venue is not bookable on the intranet`.
- **D-10 role scope: no JCRC exemption.** CONTEXT.md D-08 removes the role-conditional slot branch and D-10 says the type comes from the DB for everyone. A JCRC exemption would leave one role able to create a claim on a venue whose slots surface nowhere in the product, producing an unmanageable row. The gate applies to every authenticated caller.
- **D-04: keep the removed type's entry in `FACILITY_TYPE_CONFIG`.** `FacilityType` keeps the literal (D-04), `FACILITY_TYPE_CONFIG` is a total `Record<FacilityType, …>`, and six components index it unguarded. Deleting the entry breaks `tsc`. Instead, plan `01-02` stops the type filter from *enumerating* the config keys — see the `type-filter.tsx` finding below.
- **D-05: delete `FacilitySingleSchedule`.** `grep -rn FacilitySingleSchedule src/ tests/` returns exactly its own declaration and nothing else. It is dead, and its doc comment is the last piece of bot-ownership prose outside the exclusion itself.
- **D-14: leave the dropped-column comments alone** in `src/lib/facilities/facility-schedules.ts`, `src/app/api/facilities/schedules/route.ts` and `src/app/api/facilities/schedules/route.test.ts`. They document a schema rebuild, not this feature, they live outside the directories REBOK-06 audits, and the route test asserts accepted-and-ignored behaviour that has nothing to do with this cut.
- **`HALL_TIME_ZONE` goes with the helpers.** Its only consumer is `bookingHorizonEnd` (grep-confirmed), and its doc comment is horizon copy.
