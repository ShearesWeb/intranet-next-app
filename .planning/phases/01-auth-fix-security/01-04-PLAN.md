**Manual Set-Cookie Header Inspection (D-18):**

This step verifies the SSR session bleed fix works in a real browser with a real Supabase session.

1. Start the dev server: `npm run dev`
2. Open browser DevTools -> Network tab
3. Log in via Google OAuth
4. Wait for the access token to near expiry (or manually advance the clock -- Supabase access tokens default to 1 hour)
   - Alternative shortcut: In Supabase Dashboard -> Auth -> Configuration, temporarily set JWT expiry to 60 seconds for testing
5. Navigate to any `/dashboard/*` page
6. In the Network tab, find the SSR navigation request (the HTML document request, not XHR)
7. Check the Response Headers for `Set-Cookie` containing `sb-` prefixed cookies
8. Also verify the response includes `Cache-Control: private, no-cache, no-store, must-revalidate, max-age=0`

**Expected result:**
- `Set-Cookie` header is present with refreshed Supabase auth cookies
- `Cache-Control` header prevents caching
- User sees the correct dashboard page (not another user's data)

**Also verify (quick checks):**
- Navigate while logged in: no unexpected logouts
- Navigate to /dashboard while logged out: redirected to /auth/login?reason=session_expired
- Login form shows "Your session has expired" toast when reason=session_expired is in URL
  </action>
