# E2E Testing Harness Design

**Date:** 2026-05-23
**Status:** Approved
**Scope:** End-to-end testing infrastructure with persona-based role switching

## Overview

An E2E testing harness for the intranet Next.js app that enables both manual exploration and automated Playwright tests with instant role switching. The harness injects real Supabase sessions — the app runs completely unmodified, exercising the full auth stack (middleware, `fetchUserInfo`, role flags from the DB view).

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Auth mock strategy | Supabase session bypass | Tests the real auth stack end-to-end; no mock drift risk |
| Supabase environment | Local (`supabase start`) | Fully isolated, offline-capable, fast |
| Manual testing UX | CLI opens headed Playwright browser | Simple, no test-only UI code in the app |
| Test organization | By feature area | Natural grouping; each spec uses whatever personas it needs |
| Auth user ID strategy | Deterministic UUIDs (v5) | `seed.sql` can hardcode them; auth harness uses the same function |

## Architecture

```
┌─────────────────────────────────────────────────┐
│  CLI (e2e/cli.ts)                               │
│  npx e2e login <persona> | npx e2e personas     │
│  Manual testing: opens headed browser w/ session │
└──────────────────┬──────────────────────────────┘
                   │ uses
┌──────────────────▼──────────────────────────────┐
│  Auth Harness (e2e/auth-harness.ts)             │
│  • Connects to local Supabase via Admin API     │
│  • Creates auth user for persona (idempotent)   │
│  • Generates valid session (JWT + refresh token) │
│  • Returns cookie array ready for injection      │
└──────────────────┬──────────────────────────────┘
                   │ used by
┌──────────────────▼──────────────────────────────┐
│  Playwright Fixtures (e2e/fixtures.ts)          │
│  • asPersona(key) → authenticated Page          │
│  • Auto-cleanup after each test                  │
└─────────────────────────────────────────────────┘
```

The auth harness is the shared core. Both the CLI and Playwright fixtures consume it. The app itself is never modified — no test-only middleware, no env-var gates, no mock user objects.

## Local Supabase & Seeding

### Supabase Setup

`supabase start` spins up local Postgres + GoTrue + all services via Docker. Config lives in:

```
supabase/
  config.toml          # generated by supabase init
  seed.sql             # symlink → tests/fixtures/seed.sql
```

### Seeding Flow

1. `supabase start` / `supabase db reset` — Postgres loads `seed.sql` automatically
2. `seed.sql` populates the public schema: users, CCAs, positions, appointments
3. Auth users are created programmatically by the auth harness at test startup via `supabase.auth.admin.createUser()`

Auth users live in GoTrue's `auth.users` table (separate from the public schema), so they must be created via the Admin API, not SQL.

### Deterministic UUIDs

The `auth_user_id` in the public `users` table must match the `id` in `auth.users`. Both use deterministic UUID v5 values derived from the persona key with a fixed namespace:

```ts
import { v5 as uuidv5 } from "uuid";
const E2E_NAMESPACE = "a1b2c3d4-e5f6-7890-abcd-ef1234567890"; // fixed
function personaUUID(key: string): string {
  return uuidv5(key, E2E_NAMESPACE);
}
```

`seed.sql` hardcodes these UUIDs. The auth harness calls `personaUUID()` to generate the same IDs. No coordination needed at runtime.

## Auth Harness API

**Module:** `e2e/auth-harness.ts`

### Functions

```ts
personaUUID(key: string): string
// Deterministic UUID v5 from persona key + fixed namespace.
// Same values used in seed.sql.

ensureAuthUser(persona: Persona): Promise<string>
// Creates auth user via supabase.auth.admin.createUser() if not exists.
// Uses personaUUID(persona.key) as the user ID.
// Catches "already exists" gracefully. Returns the user ID.

getSessionCookies(personaKey: string): Promise<Cookie[]>
// 1. Look up persona from personas.ts
// 2. ensureAuthUser() — idempotent
// 3. Generate session via admin.generateLink({ type: 'magiclink', email })
// 4. Exchange link token for a full session (access_token + refresh_token)
// 5. Chunk session JSON into Supabase SSR cookie format:
//    sb-<ref>-auth-token.0, sb-<ref>-auth-token.1, etc.
// Returns Cookie[] compatible with Playwright's context.addCookies()
```

### Configuration

Read from env vars with local-Supabase defaults:

| Env var | Default | Purpose |
|---------|---------|---------|
| `SUPABASE_URL` | `http://127.0.0.1:54321` | Supabase API URL |
| `SUPABASE_SERVICE_ROLE_KEY` | Local well-known key | Admin API access |

The project ref (needed for cookie names) is derived from `supabase/config.toml` or defaults to the local Supabase ref.

## CLI Tool

**Module:** `e2e/cli.ts`

### Commands

**`npx e2e login <persona>`**

1. Calls `getSessionCookies(personaKey)`
2. Launches `chromium.launch({ headless: false })`
3. Creates browser context with cookies injected
4. Navigates to `http://localhost:3000/dashboard`
5. Prints: persona name, role flags, URL
6. Keeps process alive until browser closes or Ctrl+C

## Playwright Fixtures

**Module:** `e2e/fixtures.ts`

Extends `@playwright/test` with a persona-aware fixture:

```ts
import { test as base } from "@playwright/test";
import { getSessionCookies } from "./auth-harness";

export const test = base.extend<{
  asPersona: (key: string) => Promise<Page>;
}>({
  asPersona: async ({ browser }, use) => {
    const pages: Page[] = [];
    await use(async (key: string) => {
      const cookies = await getSessionCookies(key);
      const context = await browser.newContext();
      await context.addCookies(cookies);
      const page = await context.newPage();
      pages.push(page);
      return page;
    });
    for (const page of pages) await page.context().close();
  },
});

export { expect } from "@playwright/test";
```

Each call to `asPersona` creates an isolated browser context with its own cookies. Multiple personas can be used in a single test (e.g., testing that admin sees something a regular user doesn't). All contexts are cleaned up after the test.

## Playwright Config

**File:** `e2e/playwright.config.ts`

Key settings:
- `testDir`: `./specs`
- `webServer.command`: `npm run dev` (with env vars pointing to local Supabase)
- `use.baseURL`: `http://localhost:3000`
- No default `storageState` — each test gets its own via `asPersona`
- Single project: `chromium` (expand later as needed)
- `retries`: 0 locally, 2 in CI

## Test Structure

```
e2e/
  auth-harness.ts            # ~80 lines — session cookie generation
  cli.ts                     # ~60 lines — login + personas commands
  fixtures.ts                # ~30 lines — Playwright test extension
  playwright.config.ts       # ~30 lines — config
  specs/
    auth.spec.ts             # login redirects, session expiry, logout
    dashboard.spec.ts        # dashboard loads, role-appropriate content
    navigation.spec.ts       # sidebar items match role, route guards
    allocation.spec.ts       # CCA allocation preference flow
    holiday-subsidy.spec.ts  # subsidy declarations and approvals
    member-ranking.spec.ts   # ranking workflows
```

Tests are organized by feature area. Each spec imports `{ test, expect }` from `../fixtures` and uses `asPersona` to get authenticated pages.

### Example Test

```ts
import { test, expect } from "../fixtures";

test("admin sees member ranking page", async ({ asPersona }) => {
  const page = await asPersona("declan");
  await page.goto("/dashboard/memberRanking");
  await expect(page.locator("h1")).toContainText("Member Ranking");
});

test("regular user is redirected from ranking", async ({ asPersona }) => {
  const page = await asPersona("aria");
  await page.goto("/dashboard/memberRanking");
  await expect(page).toHaveURL(/dashboard$/);
});
```

## Developer Workflow

### First-time setup
```bash
supabase start           # start local Supabase (Docker)
npx playwright install   # download browser binaries
```

### Manual testing
```bash
npm run dev                       # start Next.js
npm run e2e:login -- declan       # open browser as admin/sports chair
npm run e2e:login -- aria         # open browser as regular user
npm run e2e:personas              # list all available personas
```

### Automated testing
```bash
npm run e2e                # headless (CI default)
npm run e2e:headed         # see the browser
npm run e2e:ui             # Playwright visual test runner
npx playwright test auth   # run only auth specs
```
